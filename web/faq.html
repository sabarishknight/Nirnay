Questions a Retail Lending head asks

Short answers to what comes up in the first meeting. If yours is not here, ask us.

Does the AI approve or reject loans?

No. The agent recommends and drafts; a credit officer decides, deviations go to the authority in your delegation of powers, and a decline always needs a person and written reasons to the applicant. The agent cannot change a file's status.

What if Gemini misreads a number in a document?

Figures that drive the decision come from independent sources where possible: salary from Account Aggregator bank data, obligations from the bureau, property value from the valuer. Document fields are used to cross-check those sources, and the officer sees every field the model read next to the PDF. A mismatch is surfaced, not silently resolved.

Can the model invent facts in the note for sanction?

The note is drafted from a structured list of verified facts, with an instruction to use only those facts and cite the clause behind each claim. The officer edits it before deciding, and the officer's version is what is recorded.

Does the AI do the FOIR and LTV calculations?

No. Arithmetic and rules run in ordinary code with parameters from the policy pack. The language model reads and writes; it does not calculate or decide.

How does it keep up with RBI and policy changes?

Policy is stored as numbered clauses with parameters. A change, such as the repo rate rising to 5.50% on 7 October 2026, is a data change, and the Policy watch re-screens every file already in progress so officers can act before sanction.

Where does our data live?

In this demo, BigQuery and Cloud Run run in the Mumbai region (asia-south1). In production the same applies, with VPC Service Controls, customer-managed keys and access by role. Customer documents never leave the bank's Google Cloud project.

How is fair lending protected?

The rules use only credit-relevant data: income, obligations, bureau history, property and legal checks. Gender, religion, caste and similar attributes are not inputs. Override rates and outcomes can be monitored by branch and segment on the lending head view.

Why one agent and not a team of agents?

Credit appraisal is a sequence a bank wants done the same way every time. One agent with a fixed workflow is easier to test, audit and explain to a regulator. It fans out only where work is independent, for the external checks.

Will it work with our loan origination and core banking systems?

Yes, through the lakehouse. Change-data-capture (Datastream) brings core banking and LOS data into BigQuery without changing those systems, and the officer desk can be embedded in the LOS screen.

What does a review cost to run?

In the demo the external calls cost about ₹80 per file at illustrative rates, and the model calls a few rupees. The larger saving is officer time: the hours spent gathering and re-keying data.

What about other loan products?

The agent's steps are general; the policy pack is product-specific. Loan against property or personal loans need a new set of clauses and a few product checks, not a new system.

How would we start?

A six-week pilot on one region's home loans: two weeks to land the data and encode the policy, two weeks in shadow mode where officers decide as today and we measure agreement, two weeks in assisted mode in two branches.
